# IT / security — footprint, risks, pipeline

## Footprint and cost

`md2nativedocx` has **no server component** run by this project. It runs on the user's machine (CLI, VS
Code extension, MCP server), in a CI runner, or in the visitor's browser (browser converter, a static page
served by GitHub Pages).

| Usual cost line | Here |
|---|---|
| Software license | $0: CC0 for this project's code, permissive licenses for its dependencies, free Pandoc (see [`legal.md`](legal.md)) |
| Server, cloud, SaaS | None |
| Software prerequisites | CLI, MCP server, extension: Node.js ≥ 18 and Pandoc ≥ 3.1.3 (the extension downloads Pandoc itself when missing). Browser converter: a recent Chrome, Edge, Firefox or Safari, nothing to install |
| Hardware | A standard workstation |
| One-time downloads | Extension: the official Pandoc binary if absent, and the .NET runtime if absent and the Word compatibility check is on. Browser converter: `pandoc.wasm`, about 17 MB compressed, kept in the browser's cache |

The real deployment cost is human: installing Node.js and Pandoc where the CLI or extension is used, and
the security review itself.

## Risk analysis

This project reads untrusted text (Markdown and diagrams written by a person or generated by an AI) and
produces files that Word, LibreOffice and PowerPoint parse: exactly the shape of document-format
vulnerabilities. The authoritative table is in [`AGENTS.md`](../../AGENTS.md) → *Security
requirements*, binding on every change; it is reproduced here to save a round trip.

| Risk | Where | Mitigation |
|---|---|---|
| XML injection through node, edge or title text | Diagram translators (`.docx`, `.odt`, `.pptx`) | Every user string escaped (`& < > " '`) before it enters XML; colours from `style`/`classDef` checked against a strict pattern. Unit tests plus property-based fuzzing |
| XXE (XML external entities) | Any XML parser, tests included | DTD processing and external entity resolution disabled everywhere |
| External relationship in OOXML (Follina class, CVE-2022-30190) | `.docx` and `.pptx` output | Never `TargetMode="External"` nor any remote reference; asserted by the translators' tests and on the CLI's real output |
| Macros, scripts, external links in ODF | `.odt` output | Never `office:scripts`, event listeners, `xlink:href` to a URL, links, DDE sources or linked objects; `.odt` schema validation must report zero errors |
| Command injection | CLI and MCP server running Pandoc | `execFile`/`spawn` with an argument array only, never a shell string |
| Path traversal | CLI paths, extension, MCP server | Paths resolved and checked against the expected root before any file operation |
| Untrusted Markdown reading local files or URLs | Pandoc, when it embeds images | `--sandbox` in the CLI (`MD2NATIVEDOCX_SANDBOX=1` in scripts), `md2nativedocx.sandbox.enabled` in the extension; always on in the MCP server, so a request cannot copy a local file into a document, fetch a URL or leak a Windows NTLM hash through a `\\server\share` path |
| PlantUML reading files or URLs | PlantUML diagrams | Parsed by this project's own code; PlantUML itself (Java) is never run. `!include` is never followed (a warning says its content is missing) and `[[url]]` links keep only their label |
| Resource exhaustion | MCP server | Each call runs in a child process killed at a deadline (30 s per diagram, 120 s per document); diagrams over 500 nodes, 800 edges or 1 M characters and Markdown over 5 M characters are refused |
| Zip bomb | Out of direct scope: Pandoc writes the packages, nothing reads an outside `.docx`/`.odt` yet | Size and ratio caps required before any future feature reads one |
| Third-party binary served to visitors (`pandoc.wasm`) | Browser converter | Official release asset only, pinned by SHA-256 at build time and checked again by the page before it runs; CSP `connect-src 'self'`, no third-party script; `pandoc.wasm` sees only an in-memory file system the page fills itself, no environment, no network |
| Downloaded binaries | Extension (Pandoc, .NET runtime) | Official publisher only, pinned SHA-256 (Pandoc) or SHA-512 (.NET), checked before extraction or execution; an internal mirror can replace the URL, never the hash check |
| Supply chain | Whole repository | `npm audit` in CI, weekly Dependabot, every new dependency justified, notices of bundled code generated and license-checked at build time |
| Release tampering | npm packages | Published only by a GitHub Actions workflow with npm trusted publishing (short-lived OIDC credential, no stored token) and provenance attestation |
| Secret leakage | Whole repository, public since its first commit | gitleaks on staged changes before each commit (local hook) and on every push and PR (CI) |
| Untested input | The Mermaid parser, the most exposed boundary | Property-based tests (`fast-check`) on that boundary, not only examples |
| Malicious dev-container config in an external PR | Codespaces | Never open an unreviewed external PR branch in a Codespace; review `.devcontainer/` and `.vscode/` diffs on github.com first |

**The VS Code extension and untrusted Markdown.** VS Code does not run the extension at all in a folder
it has not trusted (Restricted Mode). In a trusted folder, the extension treats the open Markdown as the
user's own by default and lets Pandoc read the images it names, since reports with images are its main
use. For Markdown from elsewhere, the setting `md2nativedocx.sandbox.enabled` turns on Pandoc's sandbox,
as `--sandbox` does in the CLI. Once on at any level (user, workspace, folder) it stays on, so a
repository's `.vscode/settings.json` cannot turn it off.

## What CI checks

Source: [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml),
[`codeql.yml`](../../.github/workflows/codeql.yml), [`pages.yml`](../../.github/workflows/pages.yml),
[`publish.yml`](../../.github/workflows/publish.yml).

| Check | Tool | When | Blocking |
|---|---|---|---|
| Strict typecheck | `tsc --noEmit` | Every push and PR, Linux, Windows, macOS | Yes |
| Lint and security rules | ESLint with `eslint-plugin-security` | Every push and PR | Yes |
| Unit, golden and pipeline tests | `node --test`, real Pandoc | Every push and PR, Linux (all packages), Windows and macOS (cli, core, pandoc-filter, pptx) | Yes |
| Property-based tests | `fast-check` | Every push and PR | Yes |
| Word schema validation of generated `.docx` | Microsoft's Open XML SDK | Every push and PR | Yes, for this project's own parts |
| ODF schema validation of generated `.odt` | ODF Toolkit validator, pinned by SHA-256 | Every push and PR | Yes |
| Our parser against Mermaid's own, on Mermaid's official examples | `mermaid` + `jsdom`, test-only, outside the workspaces | Every push and PR | Yes, for every example that matched before |
| Published npm packages install and run in a clean folder | `verify:npm-packages` | Every push and PR | Yes |
| Extension package builds | `vsce package`, with its own smoke tests | Every push and PR, Windows and macOS | Yes |
| Dependency audit, shipped dependencies | `npm audit --omit=dev --audit-level=high` | Every push and PR | Yes, no exception possible |
| Dependency audit, whole tree | `npm audit` with dated, justified exceptions (`audit-exceptions.json`, empty on 2026-11-28) | Every push and PR | Yes; an expired exception blocks again |
| Secret scanning | gitleaks | Every push and PR | Yes |
| Secret scanning before commit | gitleaks pre-commit hook on staged changes (`npm run hooks:install`) | Every commit on a machine where it is installed | Yes, the commit is stopped |
| Static analysis (SAST) | CodeQL, JavaScript/TypeScript | Every push and PR, and weekly | Alerts in the *Security* tab |
| DCO sign-off | `git` | Every PR | Yes |
| Visual regression (real rendering) | LibreOffice headless, pixel diff | Weekly, on release branches, and whenever a change touches the drawing code or the visual test setup | Yes when it runs |
| Browser converter before deployment | Unit tests, then a smoke test with the real `pandoc.wasm` | Every push to `main` | Yes, nothing is deployed otherwise |
| Dependency updates | Dependabot (npm, GitHub Actions) | Weekly | Opens a PR |

The badges at the top of the [`README`](../../README.md) show the latest run on `main`.

## Where the tests live

Every test is a file in the repository. [`TESTING.md`](../../TESTING.md) describes the eight chapters
(unit, pipeline, real diagram corpus, visual regression, schema validation, native Word comparison, manual
Word checklist, historical spikes), what each one catches and where it lives.

| Package | Tests |
|---|---|
| `packages/core` (parser, layout, translators) | `test/unit/`, `test/golden/`, `test/fuzz/` |
| `packages/cli`, `pandoc-filter`, `pptx`, `mcp` | `test/` in each package |
| `packages/vscode-extension` | `test/unit/` |
| `packages/web` | `test/`, and `scripts/smoke.mjs` with the real `pandoc.wasm` |
| Repository scripts (audit gate, license notices) | `scripts/*.test.mjs` |

## Dated reports

Figures in these pages are not copied by hand. Every CI run, tied to one commit, produces:

- **A summary in the Actions tab** ("Job Summary"): test count, pass/fail, coverage, written by
  [`scripts/ci-summary.mjs`](../../scripts/ci-summary.mjs) from that run's own reports.
- **Downloadable reports**, kept 90 days:
  - `test-reports-<sha>`: a `junit.xml` per package and `lcov.info` (coverage) for `packages/core`;
  - `npm-audit-<sha>`: the full `npm audit --json` output, including when the audit fails.
- **CodeQL alerts**, dated and tracked by GitHub under *Security* → *Code scanning*.

To see the state on a given date: the repository's **Actions** tab → the run for that date or commit →
*Summary*, or *Artifacts* at the bottom of the page.

Reproducible locally: `npm run build && npm run typecheck && npm run lint && npm run test:ci && npm run
test:fuzz && npm audit --omit=dev --audit-level=high`. `test:ci` writes the same reports under
`packages/*/reports/`.

## What is not covered yet

- **No required second review.** Single-maintainer project: no `CODEOWNERS` and no branch protection
  requiring another person's approval yet (see [`SECURITY.md`](../../SECURITY.md)).
- **Real Word is checked by hand.** CI validates against Word's schema and renders with LibreOffice; the
  look in real Word is checked by the maintainer for each change that affects rendering
  ([`TESTING.md`](../../TESTING.md), chapters 6 and 7), not by an automated job.
- **Pandoc versions differ by channel.** CI and the extension use Pandoc 3.1.3; the browser converter uses
  the `pandoc.wasm` of Pandoc 3.14. Bringing them together is planned.
