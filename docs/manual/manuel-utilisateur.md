# Présentation

md2nativedocx transforme un document Markdown contenant des diagrammes Mermaid en document Word (`.docx`) ou en présentation (`.pptx`). Les diagrammes ne sont pas des images : ce sont des formes Word natives, que l'on peut sélectionner, recolorer et déplacer. Le reste du Markdown est converti par Pandoc.

## Utilisation en ligne de commande

- Word : `md2nativedocx document.md -o document.docx`
- Présentation : `md2nativedocx deck.md -o deck.pptx` (une diapositive par bloc Mermaid, titrée avec le titre précédent). L'option `--show-source` affiche le code Mermaid à côté de chaque diagramme.
- Les diagrammes s'écrivent dans un bloc de code `mermaid`.

## Principes

- **Rien d'externe** : le fichier produit est autonome, sans aucune référence distante.
- **Pas d'échec silencieux** : une construction non gérée produit un avertissement (affiché et noté dans le journal d'export), jamais un diagramme faux sans prévenir.
- **Éditable, à sens unique** : les formes se modifient dans Word, mais ce qui est modifié dans Word n'est pas reporté dans le Markdown, qui reste la source de vérité.
- **Plafonds** : les entrées très grandes sont plafonnées (voir les limites de chaque type). Un diagramme mis en page automatiquement (flowchart, classes, états, entité-relation, C4, architecture, exigences) est refusé au-delà de 500 nœuds, conteneurs de sous-graphes compris, ou de 800 arêtes ; une source Mermaid est refusée au-delà de 1 000 000 de caractères.
- **En-tête YAML** (`---` … `---` avant le diagramme) : le `title:` est dessiné, comme dans Mermaid. Pour un type qui a sa propre instruction `title` (camembert, Gantt, séquence…), il en tient lieu ; pour les autres (flowchart, classes, états, entité-relation…), il devient un titre en gras au-dessus du diagramme, aligné sur son bord gauche et toujours sur la même page que lui. Les autres options (`config:`, thème, couleurs) ne sont pas appliquées, avec un avertissement : le document garde son propre style.
- **Un diagramme trop grand ne bloque pas le document** : il est remplacé par une note grise qui dit pourquoi, le reste du document (ou, pour une présentation, les autres diapositives) est converti normalement, et l'avertissement figure dans le journal d'export.
- **Utilisation par un assistant** : le paquet `@md2nativedocx/mcp` expose la conversion à un assistant compatible MCP (outils `render_diagram` et `convert_document`). Chaque appel a un délai maximal, après quoi le travail est interrompu ; le fichier produit reste dans un dossier racine choisi par l'administrateur et ne remplace jamais un fichier existant.

## Flowchart (organigramme)

Le type historique du projet : nœuds et liens avec mise en page automatique (Dagre), rendus en formes Word natives et modifiables, connecteurs attachés aux formes.

| Rubrique | Détail |
|:---------|:-------|
| Mot-clé | `flowchart` / `graph` |
| Couleurs | Oui : classDef, class, style, linkStyle |


**Syntaxe**

- Directions `TD`, `TB`, `LR`, `RL`, `BT`
- Nœuds `A[texte]`, `A(arrondi)`, `A([stade])`, `A{losange}`, `A((cercle))`, `A[(base)]`, `A[/parallélogramme/]`, etc., et la forme générique `A@{ shape: nom, label: "…" }`
- Liens `-->`, `---`, `-.->`, `==>`, `<-->`, `~~~`, avec libellé `-- texte -->`, chaînage `A --> B --> C` et groupes `A & B --> C`
- `subgraph … end` (imbriqués), liens vers un sous-graphe (`A --> S`, `S1 --> S2`) tracés jusqu’au bord de son cadre, sous-graphe replié (`S@{ view: collapsed }`) dessiné en une seule boîte grise (son titre puis « • • • »), son contenu caché et les liens vers ce contenu arrivant sur la boîte, `<br/>` et `**gras**`/`_italique_` dans un libellé entre accents graves

**Pris en charge :** Couleurs : `classDef`, `class`, `:::nom`, `style`, `classDef default` (tous les nœuds), superposés comme Mermaid (`default`, puis chaque classe dans l’ordre, puis `style`), `linkStyle` (couleur, épaisseur) ; Auto-boucles `A --> A`, diagrammes très grands (réduits pour tenir dans la page, en gardant la place d'un titre au-dessus). Une flèche qui contourne un nœud est un connecteur coudé de Word, attaché à ses deux formes.

**Limites**

- LibreOffice, quand il ouvre le `.docx`, retrace lui-même les flèches qui contournent un nœud : tout droit, à travers ce nœud ; Word et PowerPoint les dessinent correctement. Pour LibreOffice, exporter en `.odt`.
- Après déplacement d’une forme, Word recalcule lui-même le chemin d’une flèche coudée, qui peut alors passer sur un autre nœud
- `direction` à l’intérieur d’un `subgraph` : appliquée (mise en page propre au sous-graphe) tant qu’aucun lien ne relie l’intérieur à l’extérieur ; sinon ignorée avec un avertissement, comme Mermaid
- Pas de `click`, d’animation d’arête ni de formes icône/image
- SmartArt : option expérimentale, désactivée par défaut

## Diagramme de séquence

Échanges entre participants le long de lignes de vie.

| Rubrique | Détail |
|:---------|:-------|
| Mot-clé | `sequenceDiagram` |
| Couleurs | Couleurs fixes |


**Syntaxe**

- `participant` / `actor` (avec `as`), `create` / `destroy`
- Types de participant `participant X@{ "type": "database" }` (aussi `"alias"`) : chacun a son symbole UML, comme dans Mermaid. Bonhomme pour `actor` ; cercles `boundary`, `control`, `entity` ; cylindre pour `database` ; boîtes empilées pour `collections` ; cylindre couché pour `queue`

- `activate`/`deactivate`, `Note left of|right of|over`, `autonumber`, `title`
- Blocs `loop`, `alt`/`else`, `opt`, `par`/`and`, `critical`/`option`, `break`, `rect`
- Groupes `box [couleur] [titre]` … `end` : un bandeau derrière les participants du groupe, teinté si une couleur CSS est donnée (`box Purple Équipe`, `box rgb(33,66,99)`), sinon simplement encadré, le titre en haut
- Connexions centrales `()` : `A->>()B`, `A()->>B`, `A()->>()B` posent un point sur la ligne de vie, à l'extrémité marquée

**Pris en charge :** Tous les éléments ci-dessus.

**Limites**

- Demi-flèches, `link`/`links`, `properties` : reconnus, avertissement, non dessinés (un menu `link` produirait un lien vers une adresse web, ce que le projet n'écrit jamais)
- Plafonds : 50 participants, 500 éléments, 20 blocs imbriqués

> **À savoir :** les 38 exemples officiels sont comparés à l’analyseur de Mermaid lui-même (`test-corpus/mermaid-official/DIFFERENTIAL.md`) : mêmes participants, messages et blocs.

Échelle de la minute aux siècles : graduations choisies selon la durée, graphique borné à la largeur de la page. Jours exclus grisés (sinon le week-end). **Limites**

## Railroad (syntaxe)

Diagrammes de syntaxe d’une grammaire : une voie par règle, avec ses choix, options et répétitions.

| Rubrique | Détail |
|:---------|:-------|
| Mot-clé | `railroad-beta` (fonctions), `railroad-ebnf-beta`, `railroad-abnf-beta`, `railroad-peg-beta` |
| Couleurs | Couleurs fixes |


**Syntaxe**

- EBNF : `regle = "a" | b , [ c ] { d } e? f* g+ h - i ;` (`::=` accepté, commentaires `(* *)`)
- ABNF : `regle = "a" / b 1*( c ) [ d ] %x41-5A ;` (`;` termine la règle, la suite de la ligne est un commentaire)
- PEG : `Regle <- "a" / B &C !D E? F* G+ .` (`;` facultatif, commentaires `#`)
- Fonctions : `regle = sequence(terminal("a"), choice(nonterminal("b"), optional(special("c")))) ;`
- `title`, `accTitle`, `accDescr`

**Pris en charge :** Les quatre dialectes. Chaque règle a sa voie : le chemin principal reste droit, les alternatives se rangent dessous, une option passe par-dessus, une répétition boucle par-dessous (avec ses bornes ABNF, par exemple `2–5×`). Terminaux en pastilles bleues, règles en boîtes, séquences spéciales en pointillés.

**Limites**

- Exception EBNF (`a - b`) et prédicats PEG (`&a`, `!a`) : écrits en toutes lettres (« except b », « if a », « not a »)
- Une erreur de syntaxe ne bloque pas : la règle garde ce qui a été lu, avec un avertissement
- Plafonds : 200 règles, 3 000 éléments, 40 niveaux d’imbrication

| Source Mermaid                            | Rendu dans Word                                            |
+===========================================+============================================================+
| ```text                                   | ```mermaid                                                 |
| railroad-abnf-beta                        | railroad-abnf-beta                                         |
| title "Phone Number"                      | title "Phone Number"                                       |
|                                           |                                                            |
| phone = [ "+" country-code ] subscriber ; | phone = [ "+" country-code ] subscriber ;                  |
